Smart Train Ticket Booking & Checking

01

Team of 4 • 2026 • Railway web app

A smart railway application that allows users to check train locations, book train and platform tickets, and transfer a booked ticket to another available train when the original train is missed.

Key features

  • Live Train Tracking — helps users check train locations and the available trains between selected stations.
  • Easy Ticket Booking — lets passengers select trains, ticket classes, the number of passengers, and enter passenger details.
  • Smart Ticket Transfer — transfers a booked ticket to another available train and automatically compares the old and new ticket prices.
  • Secure Payments — supports UPI and card-based payments for ticket booking and for additional fare differences.
  • QR-Based E-Tickets — generates digital tickets that can be scanned and verified by ticket checkers.

Technologies used

  • HTML5
  • CSS3
  • JavaScript
  • Node.js
  • Express
  • Socket.IO
  • PostgreSQL
  • Razorpay

Integrated GIS-Based Land Governance

02

Major project • 2026 • GIS & AI

A unified GIS platform that connects land records, registration, planning, taxation, utilities and spatial data through a common parcel identity.

Key features

  • Parcel-centric GIS — connects all information to a single land parcel.
  • Survey Number + Location Search — quickly finds and highlights parcels on the map.
  • Complete Parcel Intelligence — provides ownership, registration, zoning, tax, utilities and land-use information in one view.
  • AI Land Change Detection — analyzes satellite imagery and generates alerts for potential land-use changes.
  • Citizen & Government Services — enables information requests, verification, grievance tracking, and department-level dashboards.

Technologies used

  • PostgreSQL + PostGIS
  • Leaflet.js
  • Python
  • Django
  • scikit-learn
  • QGIS
  • HTML5
  • CSS3

Praveen Hospital Appointment System

03

Team of 3 • 2025 • Healthcare web app

A smart digital platform that simplifies hospital appointment booking by helping patients find suitable doctors, check available time slots, and book appointments online.

Thinking

How I evaluate my own work

Every project above was measured against the same checklist before I published it, because “it works on my laptop” is not a standard.

Accessibility gate

Lighthouse Accessibility at 100 plus a manual keyboard pass and an axe DevTools scan with zero critical issues. Anything less is a bug, not a known limitation.

Performance gate

A 90+ Performance score on a throttled mobile profile, with a JavaScript payload under 30 kB before compression.

Resilience gate

What does the user see when the API times out or the network drops? Empty states and retry paths are designed, not improvised.

Explanation gate

If I cannot explain a design decision in three sentences, the code is too clever and gets simplified.
